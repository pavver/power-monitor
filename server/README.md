# Сервер віддаленої підтримки

Сервер, через який власник відкриває панель монітора світла, що стоїть у клієнта.
Пристрій сам звертається до сервера, тож у мережі клієнта нічого відкривати не треба.
Адреса: **https://iot.pavver.net**, адмінка: **https://iot.pavver.net/admin**.

Один сервер обслуговує всі пристрої. Новий пристрій з'являється в адмінці після першої перевірки
(чек-іну), а з прошивки адреса `https://iot.pavver.net` задана за замовчуванням
(`power_core::remote::DEFAULT_SERVER`).

## Як це влаштовано

```
браузер власника ──https──▶ Cloudflare ──тунель──▶ контейнер svitlo-remote
                                                    ├─ cloudflared   (тунель назовні)
                                                    └─ remote-server (127.0.0.1:8080)
пристрій у клієнта ─https──▶ Cloudflare ──тунель──▶        ▲
```

- Контейнер не відкриває жодного порту: сервер слухає `127.0.0.1:8080`, а назовні виходить лише `cloudflared`.
- Якщо сервер або тунель падає, зупиняється весь контейнер, і `restart: unless-stopped` піднімає обидва знову.
- Дані (`devices.json`: пристрої, хеші їхніх секретів, позначки «Чекаю пристрій») лежать у Docker-томі `server_data`.

## Файли

| Файл | Що в ньому |
| :--- | :--- |
| `compose.yaml` | Сервіс `remote`, том `data`, змінні з `.env`. |
| `Dockerfile` | Збирає `remote-server` і додає `cloudflared` (збирається з кореня репозиторію). |
| `entrypoint.sh` | Запускає сервер і тунель, зупиняє контейнер, коли падає будь-хто з них. |
| `.env.example` | Зразок налаштувань. |
| `.env` | Справжні налаштування: пароль і токен. **Не потрапляє в git.** |
| `src/` | Код сервера; `admin.html`, `admin.css`, `admin.js` — адмінка в стилі Operator. |

## Налаштування (`.env`)

| Змінна | Обов'язкова | Що це |
| :--- | :--- | :--- |
| `ADMIN_PASSWORD` | так | Пароль адмінки, щонайменше 12 символів. |
| `TUNNEL_TOKEN` | так | Токен тунелю Cloudflare. |
| `BIND` | ні | Адреса сервера всередині контейнера, за замовчуванням `127.0.0.1:8080`. Не міняйте: тунель дивиться саме туди. |
| `DATA_DIR` | ні | Тека даних, у контейнері `/data` (це том). |

Файл `.env` читається лише під час запуску контейнера. Після будь-якої зміни контейнер треба перезапустити (див. нижче).

## Пароль адмінки

Подивитися:

```sh
grep ADMIN_PASSWORD server/.env
```

Змінити: відредагуйте рядок `ADMIN_PASSWORD=…` у `server/.env` і перезапустіть контейнер:

```sh
cd server
docker compose up -d      # підхоплює новий .env і перестворює контейнер
```

Згенерувати новий пароль:

```sh
head -c 18 /dev/urandom | base64 | tr '+/' '-_'
```

Вхід у адмінку вимагає пароль і цифри з картинки (капчу). Кожна капча дає одну спробу й діє 5 хвилин.
Якщо цифри не читаються, натисніть «Інші цифри». Сесії адміна зберігаються в пам'яті сервера,
тож після перезапуску треба увійти знову.

## Перше налаштування з нуля

1. Cloudflare Zero Trust → Networks → Tunnels → Create a tunnel → Cloudflared. Скопіюйте токен
   (довгий рядок після `--token` у запропонованій команді).
2. У цьому тунелі відкрийте Public Hostname → Add: Subdomain `iot`, Domain `pavver.net`, Service `HTTP`, URL `localhost:8080`.
3. Створіть `.env`:
   ```sh
   cd server
   cp .env.example .env
   chmod 600 .env
   # впишіть ADMIN_PASSWORD і TUNNEL_TOKEN
   ```
4. Зберіть і запустіть:
   ```sh
   docker compose up -d --build
   ```
5. Перевірте: `https://iot.pavver.net/admin` показує сторінку входу.

Якщо перед доменом стоїть Cloudflare Access, шлях `/device/*` треба пропустити без входу, бо пристрої не вміють проходити SSO.

## Щоденні команди

Усі команди виконуються з теки `server/`.

| Що | Команда |
| :--- | :--- |
| Запустити | `docker compose up -d` |
| Зупинити | `docker compose down` (дані в томі лишаються) |
| Перезапустити | `docker compose restart` |
| Застосувати новий `.env` | `docker compose up -d` |
| Оновити після змін у коді | `docker compose up -d --build` |
| Стан | `docker compose ps` |
| Логи (живі) | `docker compose logs -f` |
| Логи без префікса | `docker compose logs --no-log-prefix --tail 50` |

## Резервна копія даних

```sh
docker compose cp remote:/data ./backup        # зберегти теку даних
docker compose cp ./backup/. remote:/data      # повернути
docker compose restart                         # після повернення
```

`devices.json` з'являється в теці після першої перевірки першого пристрою; до того тека порожня.

Без копії нічого страшного: пристрої зареєструються знову на наступній перевірці. Але позначки
«Чекаю пристрій» зникнуть, а якщо `devices.json` втрачено, сервер прийме перший-ліпший секрет
під кожним ID (довіра при першому контакті).

## Перевірка, що все працює

- `docker compose ps`: статус `Up`.
- У логах є рядки `listening on 127.0.0.1:8080`, `Registered tunnel connection` (до чотирьох)
  і `Updated to new configuration … iot.pavver.net`.
- `curl -s -o /dev/null -w '%{http_code}\n' https://iot.pavver.net/admin` повертає `200`.

## Якщо щось не так

| Ознака | Причина і що робити |
| :--- | :--- |
| Контейнер одразу зупиняється, у логах `set ADMIN_PASSWORD` або `set TUNNEL_TOKEN` | Змінна порожня в `.env`. |
| `ADMIN_PASSWORD must be set, at least 12 characters` | Пароль закороткий. |
| `Provided Tunnel token is not valid` | Токен скопійовано не повністю або тунель видалено. |
| Тунель підключений, але домен зависає без відповіді, і в логах немає `Updated to new configuration` | Тунелю не додано Public Hostname або hostname прив'язаний до іншого тунелю. |
| Cloudflare показує помилку 502 | Сервер у контейнері не працює: перегляньте логи. |
| Пристрій не з'являється в адмінці | Пристрій перевіряє сервер за хвилину після старту, далі раз на годину. Перевірте, що в панелі пристрою підтримку ввімкнено й адреса `https://iot.pavver.net`. |
| «Відкрити панель» довго чекає | Сесія відкривається на найближчій перевірці. Увімкніть «Чекаю пристрій», щоб перевірки йшли кожні 2 хв, або попросіть клієнта натиснути «З'єднатись зараз» у його панелі. |

## Без Docker

```sh
cd server
cargo build --release
ADMIN_PASSWORD='довгий-пароль' BIND=127.0.0.1:8080 DATA_DIR=/var/lib/svitlo ./target/release/remote-server
cloudflared tunnel --no-autoupdate run --token …
```

## Розробка

```sh
cd server
cargo test                 # сценарії пристрій ↔ сервер ↔ браузер, капча
cargo clippy --all-targets
```

Елементи керування в `src/admin.js` (Control, ripple, actionButton, textField) взяті з панелі
пристрою `firmware/ui/index.html`, тому змінювати їх треба в обох місцях. Шрифт `operator-mono.woff`
теж береться з `firmware/ui/`.
